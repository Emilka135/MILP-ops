# Голосовой ассистент регистратуры поликлиники № 7

Прототип для продуктового хакатона «Точка сборки», кейс № 2 «Голосовые интерфейсы».
Ассистент принимает входящие звонки, ведёт диалог на русском языке и **доводит
каждое обращение до реального действия в МИС**: создаёт, переносит и отменяет
записи, сообщает статус, даёт справки, напоминает о визите и переводит на
живого оператора.

Главный критерий жюри — записи и вызовы API в админке стенда «Регистратура».
Поэтому каждый успешный сценарий заканчивается вызовом `/api/v1` и попадает в
панель «Вызовы API» в интерфейсе демо.

## 1. Быстрый старт

Зависимостей, кроме стандартной библиотеки Python 3.10+, нет — устанавливать
ничего не нужно.

```powershell
python run.py
```

Откройте <http://127.0.0.1:8000>.

На этой машине интерпретатор удобнее указать явно:

```powershell
& "C:\Users\Emilka\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe" -X utf8 run.py
```

Другие полезные команды:

```powershell
python run.py --self-test              # все проверки проекта (150+) и выход
python run.py --self-test --with-http  # ещё и HTTP-API на поднятом сервере
python run.py --port 8080              # другой порт
python run.py --token <ТОКЕН>          # включить реальный стенд «Регистратура»
python run.py --build-data             # пересобрать расписание и аналитику из выгрузок
```

**Микрофон работает только на `http://127.0.0.1:8000`** (браузер требует
secure context). Если открыть `index.html` как файл, демо останется рабочим, но
только в текстовом режиме.

### Настройки через `.env`

Все настройки читаются из окружения, поэтому секреты храните в файле `.env`
(он не коммитится):

```powershell
Copy-Item .env.example .env     # затем впишите MIS_TOKEN
python run.py --env             # покажет, откуда взялись настройки (без раскрытия секретов)
```

Приоритет: аргумент командной строки → переменная окружения → `.env` →
`var/token.txt` → значение по умолчанию. Полный список ключей — в
[.env.example](.env.example).

## 2. Токен команды: как включить реальный стенд

Без токена приложение **полностью работоспособно**: оно поднимает локальный
двойник стенда, а все вызовы в журнале помечаются `source=MOCK`. Это нужно для
отладки и для показа, когда сети нет.

Когда организаторы выдадут токен команды, достаточно любого из четырёх способов:

```powershell
python run.py --token <ТОКЕН>                       # 1) аргумент
$env:MIS_TOKEN = "<ТОКЕН>"; python run.py           # 2) переменная окружения
# 3) файл .env: строка MIS_TOKEN=<ТОКЕН>  (см. .env.example)
Set-Content -Path var\token.txt -Value "<ТОКЕН>"    # 4) отдельный файл
```

После этого в шапке демо появится «стенд «Регистратура»», а в журнале —
`source=MIS`. Проверить связку заранее:

```powershell
python tools/smoke_stand.py            # GET /doctors, создание и отмена тестовой записи
python tools/smoke_stand.py --no-token # убедиться, что без токена стенд отдаёт 401
```

Адрес стенда — `https://crm-med-mock.dbi-testing.ru/api/v1` (переопределяется
`MIS_BASE_URL` или `--base-url`). Спецификация: `docs/openapi.json`.

**Что происходит при первом запуске с токеном.** Наш справочник и сетка приёма
собраны из истории записей и содержат свои `doctor_id`. У стенда — свои. Чтобы
запись не ушла к другому врачу, сервер при старте сопоставляет расписание с
`GET /doctors`: по ФИО, а если врача из истории на стенде нет — по
специальности. Сетка приёма при этом не меняется (стенд расписания не хранит).
Результат виден в `/api/health`:

```json
{"schedule_aligned": true,
 "align_report": {"mode": "stand", "mapped": 25, "by_name": 25,
                  "by_specialty": 0, "unmapped": 0}}
```

Если часть врачей стенда осталась без расписания (`unmapped` > 0), слоты по ним
не предлагаются, а в консоль выводится предупреждение — это видно и в
`/api/health`.

## 3. Что реализовано

### Сценарии

| Сценарий | Что делает | Результат в стенде | Код |
|---|---|---|---|
| **С-01** Запись на приём | идентификация → специальность → слоты → подтверждение → создание записи → SMS | новая запись «Запланирована» | `BOOKED` |
| **С-02** Запись по направлению | кардиолог/невролог/эндокринолог и др. требуют направления; без него — к участковому терапевту | запись к терапевту | `BOOKED_GP` |
| **С-03** Перенос | новая запись создаётся, и **только потом** отменяется старая | новая запись + старая «Отменена» | `RESCHEDULED` |
| **С-04** Отмена | один раз предлагаем перенос, при отказе отменяем без уговоров | статус «Отменена» | `CANCELLED` |
| **С-05** Статус записи | называем врача, день недели, дату и время | только чтение | `INFO_GIVEN` |
| **С-06** Вызов врача на дом | сбор адреса и повода дословно, заявка со статусом «Требует подтверждения» | локальная заявка | `HOME_VISIT_REQUESTED` |
| **С-07 / FAQ** Справки | режим работы, контакты, цены, график, сроки анализов, ПГГ | — | `INFO_GIVEN` |
| **С-08** Готовность анализов | только «готово / не готово», без значений | только чтение | `INFO_GIVEN` |
| **С-09** Платные услуги | цена из прайса, вне справочника — перевод в платное отделение | — | `INFO_GIVEN` |
| **С-10** Исходящее напоминание | выборка записей «на завтра», подтверждение / перенос / отмена, автоответчик, «не звоните больше» | перенос или отмена через API | `CONFIRMED`, `WRONG_PERSON`, `VOICEMAIL`, `OPT_OUT` |
| **С-11** Лист ожидания | когда слотов нет — не отпускаем без результата | локальная очередь | `WAITLISTED` |
| **С-12** Звонок за ребёнка | педиатрия для 0–17, сведения — только законному представителю | — | как в С-01 |
| **С-13** Прикрепление | справка, без идентификации | — | `INFO_GIVEN` |
| **С-14** Экстренная ситуация | красный флаг прерывает любой сценарий | перевод P1 в журнале | `EMERGENCY` |
| **С-15** Жалоба | сочувствие и перевод на старшего администратора | карточка перевода | `COMPLAINT` |

Плюс матрица маршрутизации R-01…R-17 (раздел 7.3 регламента), карточка перевода
(Приложение В) со всеми полями, локальный слой для того, чего в стенде нет
(подтверждения, лист ожидания, заявки на дом, отказы от обзвона), пост-опрос
удовлетворённости и метрики.

### Что показывает интерфейс

* лента диалога с микрофоном и текстовым запасным вводом;
* панель **«Что понял ассистент»**: интент, сценарий, состояние автомата,
  собранные параметры, вердикт safety-слоя и код правила (R-xx);
* панель **«Вызовы API»** — журнал обращений к стенду с пометкой `MOCK`/`MIS`;
  именно её сверяют с журналом админки стенда;
* **карточка перевода** (Приложение В) и экран оператора с очередью;
* **метрики и экономика** с видимыми формулами;
* 9 кнопок демо-сценариев, повторяющих раздел 7 ТЗ.

## 4. Архитектура

```
[Микрофон браузера / текст] → ASR (Web Speech API, локально в браузере)
        │
        ▼
app/web/server.py  — HTTP, статика, журнал, демо-сценарии
        │
        ▼
app/assistant/engine.py  DialogManager — конечный автомат сценариев
        │
        ├─ app/safety/detector.py   SafetyLayer  ← ПЕРВЫМ, до любой логики
        ├─ app/assistant/nlu.py     интент и параметры (правила, без внешних LLM)
        ├─ app/assistant/ru.py      русские даты, время, падежи
        ├─ app/kb/knowledge.py      база знаний из регламента
        ├─ app/assistant/slot_engine.py  свободные слоты
        └─ app/mis/client.py        клиент стенда «Регистратура»
                 └─ app/mis/mock_stand.py  оффлайн-двойник стенда
        │
        ▼
[Шаблоны реплик из регламента] → TTS (Web Speech API)
```

Три решения, которые определили конструкцию:

1. **Safety-слой стоит перед всем.** Красные флаги, «оператор», жалоба и
   медицинский вопрос распознаются до NLU и до сценария. Их не решает модель —
   это правила, которые невозможно «уговорить».
2. **Диалог — конечный автомат, а не генерация.** Критичные реплики
   (экстренная, граничная, приветствие) берутся из регламента дословно.
   Предсказуемость важнее естественности формулировок.
3. **Свободные слоты считаем сами.** Стенд расписания не знает и занятость не
   проверяет, поэтому сетка строится из истории записей, а занятость — из
   активных записей стенда.

## 5. Персональные данные и 152-ФЗ

**Всё обрабатывается в контуре заказчика.** В проекте нет ни одного обращения к
внешним сервисам: ни распознавание речи, ни синтез, ни языковая модель не уходят
в интернет.

| Компонент | Решение | Почему безопасно |
|---|---|---|
| ASR | Web Speech API браузера (на демо-стенде) | аудио не покидает рабочее место; в боевом контуре — `faster-whisper`/`Vosk` внутри периметра |
| TTS | Web Speech API браузера | синтез локальный; в боевом контуре — `Silero`/`Piper` |
| NLU | правила на Python (`app/assistant/nlu.py`) | ПДн не уходят никуда, внешняя LLM не используется |
| LLM | не используется вовсе | снимает вопрос маскирования ПДн при передаче в облако |
| Данные стенда | только вымышленные | реальные ПДн в стенд не вносятся |

Дополнительно:

* **в журналах нет открытых ПДн** — только идентификаторы стенда, инициалы и
  год рождения (`mask_name`, `mask_birth`), телефон маскируется;
* **«пациент называет первым»** — до идентификации ассистент не озвучивает ни
  ФИО, ни дату рождения, ни сведения о записях; постороннему сведения не
  сообщаются (блокирующий тест №4);
* **отказ от записи разговора** — ассистент подтверждает «запись отключена» и
  продолжает обслуживание, в журнале результат помечается как «без записи»;
* **минимизация** — для справок идентификация не запрашивается вообще.

## 7. Аналитика и экономика

Цифры посчитаны по выгрузкам `data/raw/appointments.csv` (35 470 записей,
25.03–24.09.2026) и `data/raw/calls.csv` (17 772 звонка, июнь–август 2026);
полный расчёт с формулами — в `data/metrics.json`.

**Звонки (17 772):** записан 43,0 %, справка 27,6 %, перевод 8,7 %,
**пропущен 20,7 %**. То есть ≈70,6 % звонков — типовые и автоматизируются.

**Пропущенные (3 687):**

* **1 305 звонков (7,3 % всего потока) — вне часов работы операторов**, из них
  100 % пропущены (07:xx, после 20:00, воскресенье); ассистент работает
  круглосуточно и закрывает их целиком;
* 2 382 пропущено внутри часов работы, пик — 09:00 (551 звонок, 22,8 %);
* суббота — 50,4 % пропусков.

**Ожидание на линии:** среднее 22,1 с, медиана 12 с, p90 55 с, **максимум 300 с**;
дольше нормы 30 с — 20,5 % звонков. Цель кейса ≤30 с ассистент выполняет
конструктивно: он отвечает сразу.

**Записи (35 470):** состоялись 76,3 %, отменены 12,2 %, **неявка 11,5 %**
(в условиях кейса заявлено 18–25 % — расхождение отмечено ниже). Худшие
специальности по неявкам: дерматовенеролог 18,9 %, ЛОР 17,2 %, уролог 15,5 %.

**Экономика (в месяц, ставки — параметры в `tools/analyze_data.py`):**

| Показатель | Значение | Формула |
|---|---|---|
| Автоматизированных звонков | 12 544 | 17 772 × 70,6 % |
| Высвобождено времени регистраторов | **141,5 ч (0,84 FTE)** | звонки × средняя длительность (запись 166,6 с, справка 77,6 с) |
| Экономия | **59 449 ₽/мес** | 141,5 ч × ставка часа |
| Затраты на ассистента | 33 333 ₽/мес | инфраструктура + поддержка |
| **Чистый эффект** | **26 115 ₽/мес (313 382 ₽/год)** | экономия − затраты |
| Окупаемость | 8,7 мес | вложения ÷ чистый эффект |

Потери от неявок по условиям кейса (200 записей/сутки × 18–25 % × 1 200 ₽)
составляют 43–60 тыс. ₽/сутки; снижение неявок на 30–40 % даёт 13–24 тыс. ₽/сутки.
В расчёт выше неявки не включены намеренно: в нашей выгрузке их 11,5 %, и
смешивать заявленную и фактическую базу некорректно.

## 8. Допущения и известные нестыковки

Это места, где данные, регламент и стенд расходятся. Мы выбрали поведение явно
и фиксируем его здесь.

1. **Участков нет.** Стенд не хранит прикрепление и участки, поэтому «запись к
   врачу своего участка» (регламент 2.3) реализована как «любой активный врач
   нужной специальности». В боевом контуре участок берётся из МИС.
2. **Направлений в стенде нет.** Требование направления (С-02) реализовано как
   вопрос пациенту: для кардиолога, невролога, эндокринолога, гастроэнтеролога,
   уролога и пульмонолога спрашиваем «направление есть?»; без направления
   предлагаем участкового терапевта (`BOOKED_GP`).
3. **Статуса «Подтверждена» в стенде нет** (только «Запланирована», «Отменена»,
   «Завершена»), поэтому подтверждения визита из С-10 хранятся в локальном слое
   (`var/local_store.json`) и не пишутся в стенд.
4. **Записей Excel с расписанием нет.** Сетка приёма построена из истории
   записей: рабочие дни, смены (например 08:00–14:30 и 14:00–19:30), шаг 20 или
   30 минут. Если организаторы дадут файл расписания, он главнее — загрузчик
   `tools/build_schedule.py` можно переключить на него.
5. **Стенд не мешает создавать дубли.** Занятость контролирует наш код: перед
   созданием записи слот проверяется, при «заняли, пока выбирал» предлагаются
   два ближайших варианта.
6. **Кабинетов в стенде нет.** Номера кабинетов берём из истории записей
   (`data/doctors.json`), а если их нет — не выдумываем и не называем.
7. **Разное число врачей.** В кейсе заявлено 85 врачей, в выгрузке 25; в
   справочнике стенда — свои. Ассистент всегда работает по справочнику из API и
   не предлагает деактивированных врачей.
8. **Суббота у двух врачей.** В истории у Зайцева и Орловой суббота 08:00–20:00 —
   шире регламентных 09:00–15:00. Сборщик обрезает сетку по регламенту 2.2 и
   пишет предупреждение в `data/schedule_grid.json`.
9. **Неявки.** В выгрузке 11,5 %, в условиях кейса 18–25 %. Считаем по обоим
   вариантам и в питче показываем оба числа.
10. **Стоматология.** В выгрузке стоматологов нет; острая зубная боль ведёт к
    переводу в стоматологию (R-09), а не к записи через ассистента.
11. **Дата примеров.** Регламент ссылается на 30.09.2026; «сегодня» берётся из
    системных часов, для стенда — GMT+4.
12. **Оффлайн-режим.** Без токена работает локальный двойник стенда, а вызовы
    помечаются `source=MOCK`. Это не «эмуляция успеха»: при наличии токена
    пометка меняется на `MIS`, и те же коды идут в реальный стенд.
13. **Телефония (Asterisk/SIP) не подключена** — демо идёт через браузерный
    микрофон, как и допускает раздел 7 ТЗ. SMS имитируются текстом по шаблонам
    Приложения Б.

Дополнительно, по действующей дате: **дедлайн кейса на странице GIGASCHOOL Hub
указан как 13 октября 15:40 МСК**, и на момент сборки он уже прошёл. Прототип
доведён до рабочего состояния; если срок продлён или работа идёт на доработку,
проверьте актуальные условия на платформе.

## 11. Публикация в репозиторий

Проект готов к загрузке: секретов в нём нет, выгрузки заказчика исключены,
все настройки вынесены в `.env`.

### Что уже лежит в корне

| Файл | Зачем |
|---|---|
| `.gitignore` | исключает `.env`, `var/*`, `data/raw/` (7,5 МБ CSV), `__pycache__`, IDE и ОС-мусор |
| `.gitattributes` | единые переводы строк (LF) — скрипты запускаются и на Windows, и на Linux |
| `.env.example` | шаблон настроек; копируется в `.env`, который не коммитится |
| `LICENSE` | MIT (замените, если нужна другая) |
| `var/README.md` | поясняет, какие рабочие файлы создаются и почему в них нет ПДн |

### Что НЕ попадает в репозиторий

* **`var/*`** — рабочие данные: токен (`token.txt`), оффлайн-стенд, локальный
  слой с заявками и переводами, отчёт тестов. Исключён целиком, поэтому
  случайно закоммитить токен или ПДн невозможно.
* **`.env`** — токен команды.
* **`data/raw/*.csv`** — выгрузки заказчика (записи 6,2 МБ и звонки 1,2 МБ).
  Это данные хакатона, в публичный репозиторий их выкладывать не нужно.
  Восстанавливаются одной командой:

  ```powershell
  python tools/fetch_data.py            # ищет выгрузки в папке загрузок
  python tools/fetch_data.py --check    # проверить, что уже на месте
  python run.py --build-data            # пересобрать расписание и метрики
  ```

  Если файлов нет, проект всё равно работает: `data/schedule_grid.json`,
  `data/doctors.json`, `data/specialties.json` и `data/metrics.json` уже
  собраны и лежат в репозитории.
