# Эксплуатация

Все режимы используют реальные речевые модели. Разумный стартовый ориентир — 4–8 потоков и 8 GiB RAM; это не гарантия пропускной способности. GPU необязателен. Сценарный расчёт 12/16/24/32 GiB отделён от измерений в CAPACITY.md.

Стандартный ASR: CPUExecutionProvider, 2 intra-op потока, 1 inter-op. `ASR_PROVIDER=CUDAExecutionProvider` требует GPU-сборки ONNX Runtime и драйверов, отсутствующий provider останавливает запуск. TTS принимает `TTS_DEVICE=cuda`; стандартный Compose и локальная приёмка используют CPU. GPU-профиль надо проверять на конкретной карте. BGE подключается отдельно на CPU.

Нужны токен МИС, подтверждённое расписание с явными id врачей, экспорт пациентов и телефонов. Для исходящих звонков нужны SIP-транк и заранее опубликованные официальный номер/предупреждения о мошенниках. `OUTBOUND_ENABLED=0` по умолчанию. Кампания проверяет ANTI_FRAUD_PUBLISHED; значение выставляется после фактической публикации, которую код не имитирует.

СМС-шлюз: POST `{to,text}`, заголовок Idempotency-Key, ответ `{id}`. `accepted` означает принятие шлюзом, а не подтверждённую доставку оператором связи. При отказе сообщение остаётся pending, автоматический повтор сохраняет ключ. В демо — simulated.

SQLite WAL и outbox сохраняются в clinic-data. Один токен обслуживается одним CRM-писателем и одним общим лимитом 10 RPM. Перед кампанией импортируйте/сверьте записи. Неопределённые операции после перезапуска не разблокируются автоматически.

МИС и обзвон используют GMT+4 из задания, независимо от часового пояса чата. Окно 10:00–22:00; максимум 6 попыток на телефон за скользящие сутки, 3 пары: пауза внутри пары 20 минут, между парами 3 часа. История общая для всех записей с одним номером и сохраняется в БД.

В live обязателен API_TOKEN. Панель регистратора требует тот же Bearer; для браузера используйте доверенный обратный прокси, добавляющий заголовок, либо локальный доступ. Аудиозапись на диск по умолчанию выключена, рабочие буферы ограничены. Модели работают локально. Требования к согласию, контуру обработки и организационным мерам сохранены в исходном ТЗ; техническая реализация сама по себе не является аттестацией системы.
