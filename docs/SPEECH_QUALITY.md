# Произношение и качество речи

Штатные веса: **Silero v5_cis_base**, MIT, голос `ru_ekaterina`.
Источник: [официальный каталог](https://github.com/snakers4/silero-models/blob/master/models.yml), [MIT LICENSE_CIS](https://github.com/snakers4/silero-models/blob/master/LICENSE_CIS).
Размер 91 680 514 байт, SHA256 `ba41b18f6a707ad93605a162998865e7c087153d2e010a26dd02229dab0e672a`. Загрузчик сверяет этот SHA256. `v5_5_ru` больше не выбирается автоматически; её ограничение NC не исчезает от лицензии нашего приложения.

Ни акустическая модель, ни её название не гарантируют чтение сокращений и дат. Перед моделью работает общий `calls.tts.normalize`: `СМС`/`SMS` → «эс эм эс», `16.10.2026` → «шестнадцатого октября две тысячи двадцать шестого года», `14:30` → «четырнадцать тридцать», `201` → «двести один». Телефоны произносятся привычными группами, ведущие нули и номера карт — по цифрам. Невалидная дата или нераскрытый шаблон вызывают ошибку. Латинское имя требует явного русского произношения, вместо молчаливого удаления букв.

Для CIS base ударения добавляет локальный словарь. Неизвестные фамилии всё ещё требуют проверки произношения; автоматический ASR не доказывает правильность ударения. Временное «данные из записи» в предпросмотре обозначает переменные шаблона и не является фразой рабочего звонка.

Синтез выполняется на 48 кГц с нейтральной скоростью. Затем FFmpeg `atempo` меняет темп с сохранением высоты; для телефона выполняется преобразование с фильтрацией до 8 кГц. Самописный WSOLA больше не участвует в рабочем синтезе. Для браузерной кнопки возвращается 48 кГц. Для звонка PCM остаётся 8 кГц: качество телефонной линии ограничено её полосой. Пиковый уровень ограничен без усиления фонового шума. Фраза синтезируется с воспроизводимым начальным состоянием акустического генератора.

## Проверка перед сборкой сценария

1. Администратор открывает «Аудиофразы» и обновляет записи из сценариев.
2. Нажимает **«Проверить произношение»**. Проверяется каждый текущий статический WAV: формат, длительность, уровень, клиппинг и фактическая расшифровка настоящим ASR.
3. Ошибки остаются в отчёте. Для каждого WAV сохранены ожидаемый текст, ASR-текст и SHA256. Нужные фразы прослушиваются и исправляются; затем проверка повторяется.
4. Сборка из редактора и отдельный сборщик требуют успешный актуальный отчёт. Изменённые текст, темп, WAV, модель или обработка требуют новой проверки. Черновики можно сохранять до проверки, чтобы не потерять работу.

`audio-bank/audit.json` — отчёт, `current.json` — текущая модель/голос/обработка. Старые версии остаются в банке, но не подменяют текущие фразы в интерфейсе. При замене WAV его прежняя версия сохраняется в `history/`.

Автоматический порог — WER ≤ 0,15 с отдельным точным сравнением числительных, ненулевой звук и отсутствие клиппинга. Это фильтр ошибок, а не оценка естественности и не доказательство безошибочности каждой медицинской формулировки. Изменение ответа или даты одним словом всё ещё требует содержательной проверки.

## Воспроизводимый прогон

В ML-окружении должны быть установлены `requirements/tts.txt`, `requirements/asr.txt` и FFmpeg. GPU не требуется.

```bash
python tools/download_models.py --tts --asr
PYTHONPATH=runtime/src:. python debug/run_speech_quality.py --all-phrases --out debug/runs/tts-quality/verified
```

На текущем рабочем наборе: **48/48** (42 постоянные фразы и 6 дополнительных примеров) прошли реальный TTS → WAV 8 кГц → ASR. В `debug/runs/tts-quality/verified/` для каждого примера находятся `*-48khz.wav`, `*-8khz.wav` и `result.json`. Этот набор включает ещё разрабатываемые сценарии; он не означает приёмку агента или ночных профилей. Предыдущие неудачные сравнения голосов сохранены отдельно, не выданы за успешный результат.

Чтобы послушать:

- `01-sms-48khz.wav`: СМС;
- `02-date-time-48khz.wav`: дата, время, кабинет;
- `05-identifiers-48khz.wav`: номер карты и телефон;
- рядом одноимённые `*-8khz.wav` для сравнения телефонной полосы.

При миграции старого `.env` установите `TTS_SPEAKER=ru_ekaterina`. Прежний голос `xenia` относится к другой модели. Команда штатного запуска остаётся `./clinic start`. В Compose голосовой сервис зависит от успешного одноразового `audio-check`: тот вызывает настоящий ASR для текущих записей после готовности TTS/ASR. Проверка записей отделена от скачивания Python-пакетов и компиляции Rust.
