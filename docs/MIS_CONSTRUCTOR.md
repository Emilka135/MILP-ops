# Быстрый конструктор запросов МИС

Энкодер определяет смысл и извлекает поля; `clinic.mis_contract` собирает запрос из проверенной операции `docs/openapi.json`. Сеть вызывается только после проверки. Свободный SQL, выдуманный endpoint и разрешение на запись от модели не используются.

Вход: `operation_id`, поля тела, фильтры и параметры пути. Выход: метод, путь, тело, фильтры, `missing_fields`, `invalid_fields`, `complete`. `authorized` всегда `false`: полнота данных не подтверждает пациента, направление, свободный слот или согласие. Их проверяет действующий автомат и CRM.

В сценарии доступен шаг:

```text
call crm.prepare_mis operation_id=createVisit client_id=$remote_client_id doctor_id=$doctor_id scheduled_at=$scheduled_at
ready -> confirmation
missing -> collect_missing
invalid -> operator reason=invalid_mis_fields
```

Это пример подключения к текущему состоянию: названия трёх переходов и переменные определяет сценарий. `prepare_mis` сам ничего не записывает. Недостающие `client_id` и `doctor_id` получают поиском и проверенным сопоставлением в базе, а не вопросом пациенту «назовите ID». На входе собираются ФИО, дата рождения и пожелания; подтверждённый слот даёт врача и время.

Настоящий `StrictStand.request` использует тот же конструктор перед каждым HTTP-запросом. При ошибке формы возвращаются `MIS_MISSING_FIELDS`, `MIS_INVALID_FIELDS` или `MIS_UNKNOWN_OPERATION`, без сетевого вызова и расхода лимита. HTTP 400/401/403/404/409/422/429/503 и потеря ответа проверяются отдельно; отказ сети не превращается в просьбу снова назвать ФИО.

Спецификация разбирается один раз и перечитывается при изменении файла. Поддержаны её 12 операций read/create/update, обязательные поля, nullable, типы и календарь, ограничения ID/пагинации и неизменяемые поля. Тело JSON не приводит строку `"3"` к числу `3`; пустой PATCH сохраняет смысл API. Готовая форма запроса не заменяет дополнительные правила клиники: стенд сам не запрещает прошедшее время или двойную запись.

Проверки конструктора идут в `DOCX / mis` Actions. Локально:

```bash
python -m pytest tests/contracts/test_mis_constructor.py
CLINIC_CONTRACT_RUN_ID=local-mis-check python debug/run_docx_contracts.py --module mis
```

При выборе энкодера сравниваются категории, извлечённые поля, отрицания и корректный план операции. USER-bge-m3 использует CLS + L2 и требует отдельной калибровки; префикс `query:` и mean-pooling E5 нельзя переносить механически. [Карточка модели](https://huggingface.co/deepvk/USER-bge-m3) указывает Apache-2.0; проверенная ревизия `0cc6cfe48e260fb0474c753087a69369e88709ae`. Веса и дообучение ещё не приняты. Сжатие проверяется на целевом CPU и независимом корпусе; текущий обязательный порог — 100 запросов энкодера в минуту, полный тракт — отдельно 20 звонков в минуту.
