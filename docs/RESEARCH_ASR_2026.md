# ASR: проверенные источники на 15 октября 2026

Задача — русская телефония 8 кГц, числа, даты, короткие ответы. Рейтинг ниже относится к конкретным наборам, не к универсальной «лучшей модели». Собственные измерения не смешиваются с результатами авторов.

## Русская речь: два независимых сравнения

Данные авторов GigaAM, WER %, одинаковый набор Callcenter:

| Модель | WER |
|---|---:|
| GigaAM v3 RNN-T | 9,5 |
| GigaAM v3 CTC | 10,3 |
| GigaAM v3 E2E RNN-T | 12,6 |
| GigaAM v3 E2E CTC | 13,3 |
| T-one + LM | 13,5 |
| Whisper | 23,1 |

E2E-вариант выбран ради нормализованного вывода; он не имеет тот же WER, что обычный RNN-T. Средний WER по таблице авторов: 8,3 у v3 RNN-T и 11,2 у E2E RNN-T. [Первичная таблица GigaAM](https://github.com/salute-developers/GigaAM/blob/main/evaluation.md).

Отдельный набор авторов T-one:

| Модель | Call-center WER | Named entities WER |
|---|---:|---:|
| T-one | 8,63 | 5,83 |
| GigaAM RNN-T v2 | 10,22 | 9,55 |
| Vosk ru 0.54 | 11,28 | 12,12 |
| Whisper large-v3 | 19,39 | 17,87 |

T-one рассчитан на потоковую телефонию, 71M параметров; код и модели Apache-2.0. Результаты из двух таблиц нельзя вычитать друг из друга: наборы различаются. Named entities не равны отдельному тесту чисел и дат. [Первичный репозиторий T-one](https://github.com/voicekit-team/T-one).

## Публикации 2026

1. **GigaAM Multilingual: Foundation Model for Underrepresented Languages**, Kuzmenko et al., 11.07.2026, Interspeech 2026. Работа о многоязычном обучении и балансировке данных, не доказательство готового низколатентного русского streaming-сервера. Полезна для выбора семейства моделей; приложение использует v3 E2E, не multilingual. [Статья и условия распространения](https://arxiv.org/abs/2607.10371).
2. **Streaming Speech Recognition with Decoder-Only Large Language Models and Latency Optimization**, Wan et al., 30.01.2026, ICASSP 2026. Read/write policy + MoChA; авторы сообщают CER 5,1/5,5 на AISHELL и снижение средней задержки токена на 62,5%. Это китайский язык, результаты нельзя переносить на русскую телефонию. [Статья и лицензия arXiv](https://arxiv.org/abs/2601.22779).
3. **Pushing the Limits of On-Device Streaming ASR**, Banfic et al., апрель 2026. Сравнение более 50 конфигураций и ONNX-квантизации для английского. Авторы сообщают 8,20% среднего streaming WER и 0,56 с алгоритмической задержки для выбранной конфигурации. Это ориентир методики измерения latency/памяти, а не русская модель для данного решения. [Первичная публикация](https://arxiv.org/abs/2604.14493).

Для контекста: **GigaAM: Efficient Self-Supervised Learner for Speech Recognition**, Kutsakov et al., Interspeech **2025**, использует chunkwise attention и динамическое семплирование размера чанка. Год намеренно не переименован в 2026. [Статья](https://arxiv.org/abs/2506.01192).

## Опубликованный Rust runtime Deeray

Deeray `gigaam-v3-runtime` — готовый сервер инференса, не новая акустическая модель. Поддерживает HTTP batch и WebSocket CTC с revisable/stable/final границами; код LGPL-3.0-or-later, веса внешние. Автор репозитория — Yuriy Krasilnikov / Deeray Ltd. Факт наличия Rust-реализации показывает, что Python не обязателен для serving. Код нашего приложения с этим runtime не линкуется. [Первичный репозиторий и лицензии](https://github.com/deeray-ltd/gigaam-v3-runtime).

В текущей сборке проверяемый основной тракт — локальный ONNX batch по репликам. Сохранённый клиент frontier и API partial позволяют дальнейшее подключение Deeray; live WS-интеграция и точность runtime на телефонных записях здесь не заявляются измеренными. Связь с упомянутым Крыловым — в отдельном [документе](RESEARCH_KRYLOV.md).

## Числа, даты и выбор

Использованные источники не дают сопоставимого рейтинга именно по русским датам/СНИЛС на нашем телефонном канале. Поэтому приложение сравнивает канонические значения, а не только WER: «четырнадцатого октября» → ISO-дата, «четырнадцать тридцать» → 14:30, варианты частей дня → один enum. Финальная запись подтверждается пациентом и МИС.

`debug/run_speech_roundtrip.py` проверяет настоящий цикл Silero → G.711 A-law → ASR → нормализатор при 1,3/1,5/1,75×. `runtime/tools/e2e_tts_asr.py` сохранён для расширенного синтетического корпуса; его режим sim не считается аудиораспознаванием. Записи реальных разговоров в предоставленных архивах не найдены. Для будущих согласованных записей есть `runtime/tools/cluster_calls.py`: транскрипция → кластеры → черновик .flow, требующий проверки человеком.
