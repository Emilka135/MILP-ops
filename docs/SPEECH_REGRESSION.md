# Речь: фиксированный корпус, ударения и имена врачей

Рабочий TTS: MIT `v5_cis_base.pt`; расстановка ударений: `silero-stress==1.5`, режим `context`. Обрабатывается вся фраза с контекстом омографов, сохраняются явные `+` и `ё`. Явный режим не переходит молча на словарь, когда пакета/весов нет. Источники лицензий и API: [silero-stress](https://github.com/snakers4/silero-stress), [Silero CIS license](https://github.com/snakers4/silero-models/blob/master/LICENSE_CIS). Старая NC-модель не используется для новых примеров.

Диапазон runtime TTS — 0.5–2.5×; корпус проверяет требуемые 0.75 и 2.5×. FFmpeg получает цепочку `atempo` со ступенями не выше 2×; тембр не ускоряется пересэмплированием. CPU TTS и CPU ASR в этом прогоне не являются доказательством CUDA.

## ФИО врачей

TTS RPC `bank.doctors.refresh` принимает **полный текущий** справочник `{"doctors":[{"id":1,"full_name":"Семёнов Алексей Петрович","is_active":true}],"rate":1.5}`. Он заранее записывает полные имена, сохраняет атомарный индекс `doctors.json` и возвращает SHA256 справочника. Повторный снимок повторно использует WAV; новое имя/произношение/модель получают новый ключ. Неактивные/удалённые врачи исключаются из активного индекса; исторические записи остаются для отката. Ошибка синтеза сохраняет прошлый полный снимок.

`say/synth` использует готовую полную фамилию, имя и отчество внутри динамического предложения; вокруг имени синтезируются только остальные слова, `audio_source=doctor_bank_composite`. Совпадения только по полному имени и той же скорости, без угадывания склонения. Другие формы/скорости проходят обычный TTS. До первого успешного прогрева работает динамический синтез; этот статус нельзя объявлять готовым банком.

CRM должен отправлять снимок после успешного импорта/чтения справочника отдельным ограниченным фоновым worker: `TTS_DOCTOR_BANK_SYNC=1`. RPC прогрева имеет timeout120с; ожидание прогрева не должно блокировать транзакции МИС. Проверки не включают этот флаг и не вызывают живые сервисы. Импорт без `CRM.pull` требует того же явного RPC после импорта.

## Корпус для Actions

`tests/fixtures/speech_regression/` содержит 18 настоящих моно PCM16 WAV8кГц, шесть синтетических фрагментов сценариев, четыре голоса, seed20261022. `spec.json` фиксирует выбор голоса/темпа на реплику; `manifest.json` фиксирует SHA256 каждого WAV, спецификации и весов, версию stress и pipeline. Это вымышленные данные без записей пациентов. WAV публикуются в Git вместе с manifest, веса не публикуются. Размер набора <2МБ; внешний download в Actions не нужен.

Генератор `tools/build_speech_corpus.py --model /models/v5_cis_base.pt` предназначен для **новой версии** набора и отказывается перезаписывать существующий. В Actions запускать `tools/verify_speech_corpus.py --output <report.json>`; для настоящего ASR — `--real-asr`, локальные onnx веса и явный `ASR_MODEL_PATH`. В Actions не запускать генератор, reasoning API или внешние записи МИС. Целевые исходы в manifest — семантические ожидания, а не свидетельство прохождения конечного автомата: интеграционный runner обязан сопоставить реальные trace/state и завершиться ошибкой при несовпадении. Общий timeout600с, сценарий60с зафиксированы в spec; runner обязан применить лимиты.

Проверено отдельно: 18/18 WAV имеют ненулевой голосовой сигнал, нужный формат, неизменные хэши, без клиппинга. Настоящий GigaAM CPU ASR: 15/18 прошли строгую текстовую политику; три числовые формы оставлены `needs_review` в `debug/runs/speech-regression/corpus-asr.json` (дата словами/числами, `14 часов`/`14:00`, диапазон часов словами/числом). WAV не изменялись после обнаружения. Требуется независимая проверка нормализованных доменных значений и реального перехода FSM. ASR не доказывает естественность голоса или правильное ударение: слушать native48кГц и phone8кГц примеры `debug/runs/speech-regression/runtime/doctor-selection-*.wav`.
