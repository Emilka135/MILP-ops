# Быстрый запуск редактора и кэши

Обычная админка — лёгкий Python + собранный браузерный клиент. Rust, Cargo и веса моделей в её образ не входят. Первый запуск может загружать базовые образы; дальнейшие сборки используют слои Docker.

```bash
# Первый запуск / после изменения кода:
./clinic start editor
# Обычный запуск готовой версии, без проверки сборки:
./clinic start editor --no-build
```

`npm ci` выполняется до копирования UI-исходников; npm использует отдельный BuildKit cache mount. Изменение компонента не переустанавливает зависимости. TTS хранит WAV в именованном томе `audio-bank` и повторно не генерирует неизменённые фразы. `audio-init` один раз выставляет владельца **только этого тома**, затем завершается; у него отключена сеть и ограничены capabilities.

Сборщик сценариев запускается отдельно, когда нужна кнопка сборки версии:

```bash
EDITOR_ALLOW_BUILD=1 docker compose --profile builder up --build -d scenario-builder scenario-editor
```

Он получает сохранённый снимок проекта через общую очередь в `editor-data`, проверяет его заново и собирает фиксированный Rust-проект. У сборщика нет сети во время выполнения. Зависимости Cargo загружаются при сборке образа отдельным слоем по `Cargo.toml`/`Cargo.lock`, до копирования исходников; повторные Rust-сборки используют том `editor-cargo`. Артефакт содержит ревизию сценария и хеш исходников движка. Установка новой версии остаётся отдельным обновлением оркестратора после завершения активных звонков.

Эти тома использует Docker на своём разделе; на проверяемой машине его data-root — `/mnt/docker_space/docker`. Не очищайте `editor-cargo`, npm/BuildKit cache и рабочие модели ради косметической уборки: они сокращают повторный запуск. Старые ZIP-экспорты и завершённые временные части загрузок удаляются отдельно.

На этой машине DNS/маршрут обычной сети Docker не достигал Debian/npm; локальный `compose.override.yaml` задаёт build network `host`. Это настройка окружения, не зависимость проекта от сети хоста при работе. На нормальной сети override не нужен.

Фактический замер: `python debug/run_editor_cache.py`. Отчёт и полные логи двух сборок/запусков лежат в `debug/runs/editor-cache/`. Размеры и времена — локальные измерения, а не гарантия для другой машины.

Ошибка `EAI_AGAIN registry.npmjs.org` означает сбой DNS во время сборки. Для Linux с таким окружением можно создать локальный `compose.override.yaml`:

```yaml
services:
  scenario-editor:
    build:
      network: host
```

Compose автоматически подхватит его при обычной команде без `-f`. В образе npm использует локальный кэш, таймаут одного сетевого запроса 20 секунд и не больше одного повтора; прежние многоминутные повторы DNS не сохраняются. Если архив пакета уже есть в кэше, npm использует его через `--prefer-offline`.

Главный образ Rust также использует отдельные BuildKit-кэши Cargo registry/git/target. Итоговый бинарник копируется из кэша в обычный слой, поэтому очистка кэша не ломает уже собранный образ. Измерение `debug/runs/hosted-publish/cache-result.json`: повтор без изменений 1,646 с, пересборка после комментария в Rust-исходнике 4,967 с, восстановление исходника 0,948 с. Менялся только изолированный снимок в debug; проверяемая ветка не менялась ради замера.


Для всей уже собранной GPU-копии: `./clinic start --gpu --no-build`. Этот путь не запускает сборку и не требует повторного получения metadata базовых образов. После изменения кода нужен новый образ: `--no-build` запускает сохранённую версию.

19.10.2026 обычная сборка редактора дважды получила сетевой EOF при анонимном запросе `auth.docker.io` для Dockerfile frontend. Кэш npm до этого этапа ещё не использовался; отсутствие рабочего Docker Hub не исправляется переустановкой пакетов. Локальная копия обновлена из собственного установленного runtime-образа и проверенного UI/dist, исходники и Dockerfile временной сборки сохранены в `debug/runs/ci-repair/editor-cached-build/`. Это временный способ развёртывания, обычная сборка с нуля остаётся отдельной проверкой после восстановления сети.
