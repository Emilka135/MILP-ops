# Контракт МИС

Источники — docs/openapi.json из MILP-ops и исходное ТЗ. 17.10.2026: токен команды сохранён только в локальном `.env` (0600, исключён из Git). Настоящий `GET /api/v1/doctors?limit=1&offset=0` вернул HTTP 200. Создание/изменение записей этим прогоном не выполнялось. Документация сервера: https://crm-med-mock.dbi-testing.ru/docs ; спецификация — `/docs/openapi.json`. Локальная приёмка изменений использует изолированный HTTP-двойник того же контракта.

| Действие | Запрос |
|---|---|
| Пациент | POST /clients: last_name, first_name, birth_date, optional middle_name |
| Запись | POST /visits: client_id, doctor_id, scheduled_at |
| Перенос | PATCH /visits/{id}: doctor_id, scheduled_at |
| Отмена | PATCH /visits/{id}: status=Отменена |
| Подтверждение | локальный bookings.confirmed: в API такого статуса нет |
| Заявка специалисту | POST /escalations: client_id, description (до 1000 символов); реальное соединение отдельно |

Base URL включает /api/v1. Даты — ДД.ММ.ГГГГ, момент приёма — ДД.ММ.ГГГГ ЧЧ:ММ, GMT+4 без смещения. Пагинация limit=50/offset. Все запросы одного токена расходуют единый бюджет 10 за скользящую минуту. 429 не превращается в объявленный успех.

## Канонические импорты CSV / XLSX

Расписание CRM_SCHEDULE; doctor_id совпадает со стендом, не с номером строки:

```csv
doctor_id,full_name,specialty,cabinet,date,start,end,slot_minutes,is_active
85,Иванов Иван Иванович,терапевт,201,2026-10-16,09:00,13:00,20,1
```

Это пример формата, не настоящее расписание. Справочник без расписания не создаёт свободные слоты.

CRM_PATIENTS:

```csv
id,last_name,first_name,middle_name,birth_date,snils,card_no,phone,stand_client_id
3,Тестова,Мария,Сергеевна,1992-11-23,32345678901,1003,79165550000,
```

ФИО берутся из доверенного импорта, у звонящего не спрашиваются. stand_client_id задаётся только при подтверждённом сопоставлении; иначе при первой записи выполняется идемпотентная регистрация /clients.

CRM_BOOKINGS:

```csv
remote_id,patient_id,doctor,starts_at,confirmed
105,3,85,2026-10-16T09:00,0
```

Импорт занимает соответствующий слот. sync_pull читает страницы врачей/записей; создаёт локальные записи только с явным сопоставлением remote_clients. Неизвестный пациент всё равно занимает слот как external; ручной перенос известной записи сохраняет её id и освобождает старый слот, отмена/завершение освобождает занятое время. Конфликт сторонних писателей блокирует спорный слот и создаёт заявку оператору. Никаких угадываний личности по совпадению id.

POST /v1/stand.status показывает operations: pending/done/failed/uncertain. Для uncertain регистратор сверяет фактический визит со стендом и разрешает конфликт в зеркале. Автоматического повторного POST /visits нет: стенд не гарантирует его идемпотентность.

Сверка ручных действий регистраторов явная, не непрерывная подписка. Перед пилотом зеркало должно владеть автоматическими слотами либо синхронизироваться с другими писателями. Текущий sync_pull не является полным обработчиком всех конфликтов сторонних переносов; такие конфликты требуют сверки человеком.

## Подключение команды и VM

`APP_MODE=demo` всегда оставляет звонки локальными, даже если токен уже сохранён. Для настоящего режима установите `APP_MODE=live`, `STAND_URL=https://crm-med-mock.dbi-testing.ru/api/v1` и `DBI_API_TOKEN` (либо `STAND_TOKEN`, который имеет приоритет). Compose не передаёт ключ браузеру. На VM переменные находятся в `/opt/hackathon/ai.env`; импортируйте их в окружение перед запуском, не копируя секреты в README или Git.

Перед настоящей записью импортируйте расписание с реальными doctor_id и сопоставление пациентов; демо-номера врачей использовать нельзя. API содержит справочник врачей, но не endpoint свободных слотов: доступность вычисляется из расписания и занятых визитов. Проверка токена: `python debug/run_dbi_contract.py`. Она выполняет только один GET справочника, выводит HTTP-статус и имена полей, не токен и не карточки пациентов.

В Swagger нажмите Authorize и укажите командный Bearer-токен. Чтение: GET `/doctors`, GET `/visits` с фильтрами; регистрация: POST `/clients`; запись: POST `/visits`; перенос/отмена: PATCH `/visits/{id}`. Демо наблюдателя не вызывает эти операции. Запросы записи не повторяются автоматически при потере ответа.

Публичное демо VM должно слушать `0.0.0.0:8000`. Пока SSH-бастион отвергает имеющийся ключ, локальный URL не является адресом VM и публикация в Gitea не заявляется.

POST `/escalations` не идемпотентен; автоматический повтор создаст дубликат. Наш локальный operator_requests/ARI пока не отправляет эту новую заявку, подключение отмечено в TODO.
