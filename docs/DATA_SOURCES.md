# Источники данных в административной панели

Откройте **Настройки → Источники данных** на http://localhost:8090.
Администратор может добавить локальный путь либо HTTP/HTTPS-ссылку, в том числе
на страницу сайта или JSON API. Для источника задаются имя, назначение и участие
в обновлении. Ссылки сохраняются в томе редактора и переживают перезапуск.

**Проверить и показать** сохраняет адрес, читает источник и показывает содержимое,
время проверки по Москве, размер и SHA256. HTML преобразуется в текст; скрипты
не исполняются. JSON показывается как данные. Сайты с загрузкой содержимого через
JavaScript требуют прямой ссылки на данные или API. Пароли и логины внутри URL
не принимаются; авторизация закрытых API отдельным адаптером пока не реализована.

**Обновить таблицы из источников** загружает по одному включённому источнику
расписания XLSX, истории приёмов CSV и событий звонков CSV в уже поддерживаемой
структуре выданных файлов. Прямые HTTP-ссылки на CSV/XLSX также поддерживаются.
Новый снимок проходит импорт и подключается только после успеха. При ошибке сети,
формата или структуры предыдущие таблицы продолжают работать. Сохранение списка
источников само по себе не заменяет активные таблицы. Источники и фактически
загруженная версия показаны отдельно.

Справочные сайты не становятся автоматически ответами голосового помощника и
не создают расписание. Их ссылки доступны для просмотра; отключение удаляет их
из публикуемого списка. Полное прочитанное содержимое находится в административном
предпросмотре. Удаление источника удаляет его кэш, сохраняя активную БД и архивы
звонков. Хранятся два последних снимка таблиц.

В контейнере исходные документы доступны напрямую в `/source-files` (только файлы
верхнего уровня), добавленные файлы — в `/imports`. Выход за эти каталоги и выход
через символьные ссылки запрещены. Источники и управление ими доступны только
администратору, записи дополнительно проверяют Origin. Ограничение чтения — 16 MiB
на источник и 256 MiB распакованного XLSX. HTTP-запросы не получают ключи модулей
и cookie администратора.

Обычная Docker-сборка редактора устанавливает `requirements/editor.txt`.
Для локального обновления без сети `tools/update_local_images.py` использует
те же версии openpyxl/et-xmlfile из уже установленного собственного CRM-образа.
Реальное отсутствие Excel-парсера в прежнем образе обнаружено браузерным импортом
и исправлено; успешное чтение ссылки не выдается за успешное обновление таблиц.

Проверки: `debug/runs/data-sources/`. В настоящем Chrome проверены ввод ссылки,
чтение HTML, сохранение после reload, отключение, импорт всех трёх исходных файлов
и доступность тестового звонка после переключения БД. Снимки просмотрены.

Для повторения локальной браузерной проверки выполните `node debug/run_data_sources.mjs`
при работающем Docker-стенде. Runner сам создаёт и удаляет собственный временный
HTTP-контейнер в сети проекта, затем удаляет только добавленный им тестовый источник.
Он намеренно обновляет таблицы из трёх заданных исходных файлов.
