# Цель и условия приёмки

Собрать работающий голосовой помощник регистратуры из MILP-ops и calls-arena, с заменяемой МИС, визуальным управлением и воспроизводимой проверкой. Ветка: `feature/rust-clinic-voice`. Заказчик определяет поведение; при расхождении комментарии заказчика имеют приоритет над исходным регламентом. Данные четырёх исходных файлов условные: Магас — город организаторов, а не доказанный адрес клиники. Телефон `+7 (000) 700-07-07` не идентифицирует реальное учреждение.

## Правило завершения модуля

Модуль принят только после проверки перечисленных условий. Код, конфигурация, документация и необходимые проверки модуля входят в отдельный подписанный коммит. Результаты запуска сохраняются в `debug/runs/<понятное-имя>/`, команды проверки — в `debug/`. Незавершённые изменения другого модуля в коммит не включаются. Зависимость от ещё не принятого модуля указывается явно. После приёмки обновляются таблица ниже и журнал коммитов; затем коммит отправляется в ту же ветку. Секреты, аудио с данными пациентов и исходные выгрузки в Git не попадают.

### Уточнение рабочего места регистратора

Для регистратора основной интерфейс — простой диалоговый экран, похожий на игру: «Открыть звонок X» → расшифровка и путь разговора → тема и альтернативные формулировки → поле правильного ответа → «Предложить исправление». Код, SQL и технический граф ему не нужны. Исправления сохраняются как размеченные примеры с исходным звонком, темой, правильной веткой и ответом; начальных данных для автоматического обучения нет. Ночью ИИ кластеризует и предлагает дополнения; утверждённый эксперимент действует временно только для номера автора и не раньше следующих суток. Жалоба приостанавливает эксперимент. Обязательны разграничение ролей, срок действия и возврат исходного варианта. Эти условия дополняют модуль 13; они пока не приняты.
