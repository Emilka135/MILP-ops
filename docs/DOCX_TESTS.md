# Контракты исходного регламента

Workflow `.github/workflows/docx-contracts.yml` запускается на push и pull request. CPU, без LLM и ключей. Независимые jobs: источник, классификация, поля, реальный скомпилированный Rust-автомат, HTTP-контракт МИС, включение постоянных фраз в предзапись и производительность NLU. Отказ одной группы не отменяет остальные.

`C-01…C-15` — ASCII-запись исходных `С-01…С-15`; `.01` — пример триггера, `.D-06` — строка приложения Д, `.label/.entities/.fsm/.mis/.audio` — модуль. `ALL` обозначает межсценарное правило. Ошибка содержит ID, ожидаемое и фактическое значение. JSON/JUnit и полный traceback находятся в артефакте `docx-contract-<модуль>`; локально — `debug/runs/docx-contracts/`.

```bash
export CLINIC_CONTRACT_RUN_ID="local-$(date -u +%Y%m%dT%H%M%SZ)"
python -m pip install -r requirements/dev.txt
python tools/download_nlu.py
cargo build --locked --bin contract-replay
python debug/run_docx_contracts.py --module source
python debug/run_docx_contracts.py --module label
python debug/run_docx_contracts.py --module entities
python debug/run_docx_contracts.py --module fsm
python debug/run_docx_contracts.py --module mis
python debug/run_docx_contracts.py --module audio
python debug/run_nlu_capacity.py
python debug/check_docx_coverage.py
```

Все модули одного прогона используют один `CLINIC_CONTRACT_RUN_ID`; Actions задаёт `run_id-run_attempt`. Отчёт связан с Git SHA, хэшем исходников/сценариев и SHA JUnit. Старый, подменённый, неполный или чужой отчёт не закрывает coverage. Перед pytest старый JUnit удаляется; общий timeout модуля по умолчанию 300 секунд, `--timeout` меняет его явно. Контрактные тесты блокируют внешние TCP-соединения и используют только локальные disposable sinks. Секреты внешних МИС/LLM очищаются в процессе runner.

Workflow `score-acceptance.yml` отдельно запускает проверки целостности доказательств, конструктора МИС, изменений администратора и предварительных предложений регистратора. Прогон через act от 22.10.2026: 64 + 27 проверок passed, `debug/runs/score-act/control-fixed.log`. Это не результат полного DOCX/ASR/внешнего стенда.

Группа `audio` проверяет, что постоянный ответ настоящего автомата включён в набор обязательных записей. Настоящие WAV, слышимость и обратное распознавание проверяет отдельный `containers-and-sbom`; принадлежность фразы к реестру не заменяет прослушивание.

`data/acceptance/docx_index.json` содержит ссылки и хэши текста в уже опубликованном `data/reglament.txt`. Полный DOCX остаётся локально. Индекс учитывает 15 сценариев, 16 контрольных диалогов и 205 примеров/ветвей. Дополнительные разделы документа отмечены как требования; их присутствие не доказывает реализацию. Абзацы оглавления 22–92 не входят в текстовый экспорт.

Обязательный job `coverage` требует, чтобы каждый из 205 примеров имел успешные проверки необходимых модулей с JUnit-свойством `source_case=<C-NN.P-NNNN или C-NN.B-NN>`. Регистрация текста, сбор testcase, `skip` и старый зелёный прогон не принимаются за исполнение. Отсутствующая реализация даёт `C-NN.B-NN.fsm.coverage: UNCOVERED`. Сейчас полное соответствие 205 примерам не достигнуто; gate намеренно показывает этот долг. Свойство следует привязывать к конкретному исходному условию и проверять результат; нельзя размечать им несвязанные тесты ради зелёного статуса.

NLU-триггеры из паспортов уже включены в эталоны `SemanticInterpreter.source_examples()`: это обязательные регрессионные случаи, а не независимый holdout для обучения. Контрольные диалоги, отрицания, ветви и новый независимый набор нужны отдельно. Нельзя обучать модель на тестовой части и затем выдавать её за независимую оценку.

Порог NLU — 100 реальных запросов максимум за 60 секунд при CPU-only inference, двух потоках и affinity на два ядра. Загрузка и прогрев показываются отдельно. Требование полного тракта — 20 звонков в минуту; оно не считается выполненным по скорости одного энкодера. Сжатие слоёв и N:M требуют повторного замера на целевом CPU и сохранения качества, отрицаний, полей и правильных запросов МИС.

МИС здесь — изолированный контрактный HTTP-сервер и настоящий SQLite. Эти проверки не утверждают доступность внешнего стенда и не используют токен команды. Переходы автомата используют `Session` из текущей Rust-сборки; CRM-вызовы контрольных диалогов исполняются настоящим `ClinicCrm`. Облачная модель и генерация SQL тестом не подставляются.
