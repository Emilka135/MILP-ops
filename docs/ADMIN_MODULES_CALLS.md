# Настройки, проверяемая запись и журнал разговоров

В админке http://localhost:8090 доступны «Настройки», «Звонки и таблицы» и «Собрать сценарии». Для администратора — текущая проектная учётная запись. Без пароля: http://localhost:8090/registrar, пробный звонок.

## Модули

`module_settings.py` хранит отдельную конфигурацию ASR, TTS, NLU, агента выбора талонов, картотеки, уведомлений, передачи сотруднику и расширений. `modules.json` живёт в томе editor-data; остальные сервисы читают его только для чтения. `ConfiguredService` проверяет enabled до создания/вызова адаптера и перечитывает конфигурацию между операциями. До первого сохранения сохраняются параметры существующего окружения.

Для ASR/TTS/NLU/агента доступны local, OpenRouter и совместимый API. Для прикладных модулей выбирается их локальный адаптер, а не речевая модель. Кнопка «Загрузить модели OpenRouter» фильтрует официальный каталог по модальности. Ввод произвольного ID не означает наличие у модели нужного API или права доступа. Голос задаётся отдельно.

Ключи не передаются через форму: задайте переменную окружения, подключённую в Compose, либо файл из `MODULE_SECRETS_DIR`. Для OPENROUTER_API_KEY поддерживается `openrouter.key`, для OPENAI_API_KEY — `openai.key`. Файл должен читаться пользователем соответствующего контейнера. В интерфейсе хранится только имя переменной. Менять доступ к секретам и подключать непроверенный облачный сервис автоматически система не будет.

TTS использует `/audio/speech`, декодирует аудио FFmpeg и возвращает штатный PCM 48/8 кГц. OpenRouter ASR использует JSON `/audio/transcriptions`; совместимый ASR — стандартную multipart-загрузку WAV. NLU сохраняет локальные проверки экстренных/медицинских обращений перед облачной классификацией. Агент сохраняет прежнюю строгую схему и проверяет выбранный ID по полученным слотам. Облачные ошибки не включают другой провайдер молча.

Настоящие облачные запросы данным модулем не приняты: контрактные проверки отделены от живого TTS/ASR. Текущий рабочий режим локальный. Пробный звонок использует собственный детерминированный сценарий и отдельную SQLite; модель подбора талонов телефонного маршрута `assisted` не выдаётся за модель этой песочницы.

## Сценарий тестового звонка

Голос, текст и клавиши идут по одному состоянию. «Глазник», «окулист» и «офтальмолог» выбирают одну специальность. Приветствие и «алло» подтверждают связь; «что?» повторяет текущий вопрос без потери выбранного врача. Ругань переводит в ветку сотрудника с `abusive_language`. Операция/лечение — нестандартное медицинское обращение, а не автоматическая запись на консультацию. После двух запросов вне регистратуры или трёх нераспознанных ответов выбирается сотрудник.

По исходному регламенту РГ-ТЕЛ-01 §2.3 хирург/офтальмолог/ЛОР доступны напрямую, кардиолог и ряд других специальностей требуют направления. Слова «направление есть» не заменяют строку в таблице referrals.

После выбора специальности обязательны полные ФИО и дата рождения, совпадение с картотекой, проверка направления, свободные актуальные талоны, выбор даты/времени и отдельное подтверждение. Только затем создаётся строка bookings. Выбор специалиста сам по себе ничего не записывает. Перед вставкой повторно проверяются карточка, направление и талон; SQLite UNIQUE(slot_id) защищает от двух подтверждений одного талона.

`SandboxStore` не подключается к настоящей МИС. patients/referrals/slots/bookings/queries видны через «Таблицы и запросы». В queries — реальные параметризованные запросы, параметры и результаты. Указание `synced_at` означает обновление **синтетического стенда**, не синхронизацию с поликлиникой. Время тестовых талонов генерируется относительно дня запуска. В базе нет настоящих пациентов. Пример: Иванов Иван Иванович, 12.04.1985; Петрова Анна Сергеевна, 23.08.1990. Направления по умолчанию пусты.

## Архив и согласие

Долговременные данные: editor-data `/data/call-log/sandbox.sqlite` и `/data/call-log/calls/`. Каждый шаг сохраняет исходную реплику, источник (ASR, клавиша, набранный текст), номер посещения шага, маршрут, версию политики и снимок правил. Сбой TTS сохраняет текст и показывает ошибку; разговор можно продолжать текстом/клавишами.

Временные WAV находятся в `/tmp/clinic-call-tmp`; входной микрофонный WAV удаляется также при ошибке ASR. Импортные буферы ограничены и истекают через 15 минут; контейнерный /tmp не является архивом. Галочка согласия снята по умолчанию. Только согласие сохраняет звук пациента и помощника в каталоге звонка. Звук воспроизводится администратором из архива. Тексты сохраняются независимо от этой галочки. Возможность отзыва согласия после начала и промышленная политика удаления — отдельная работа.

В «Звонки и таблицы» основной граф — сохранённый путь разговора. Нажатие шага раскрывает другие ветви; показываются реплики именно этого посещения, включая возвраты. У каждой записи сохранён снимок графа: последующая правка правил не заменяет историю.

## Импорт сотрудник — пациент

Принимается текст до 100000 символов: каждая строка начинается с `Пациент:` или `Сотрудник:`. WAV до десяти минут / 128 MiB браузер декодирует в моно и отправляет короткими фрагментами. ASR не разделяет говорящих автоматически: перед анализом нужно разметить роли в расшифровке. Фрагменты с тишиной не вызывают ASR.

Импортный анализ сохраняет исходные слова, сопоставляет шаги с текущим тестовым сценарием, показывает ожидаемый ответ отдельно и отмечает неопределённые сопоставления `needs_review`. Он не обращается к рабочим таблицам пациентов/слотов и никогда не оформляет запись. Подтверждение в разговоре отмечается как «со слов участников» с флагами непроверенной личности/направления и результата МИС. Это проверяемая разметка по ограниченному сценарию, не обещание автоматически восстановить любой возможный разговор. Обе стороны разговора сохраняются без подмены сгенерированными репликами. Аудио из временного буфера переносится в архив только при согласии; иначе буфер удаляется после сохранения текста.

## Необязательные расширения

client_tags, preferences, scenario_extensions по умолчанию выключены. Их можно полностью отключить. Системная причина передачи сохраняется в самом звонке даже при отключённых долговременных метках клиента.

При включённых предпочтениях явное «предпочитаю вечером» сохраняет часть дня после идентификации и ограничивает предложения сейчас и в следующих тестовых звонках. При отключении сохранённая история не влияет на подбор. Метки клиента хранятся только после идентификации; отключение прекращает их обновление.

События задают точную фразу, ответ и шаг. «Собрать сценарии» создаёт версию ответов для новых тестовых звонков. Глобальные события доступны админу; сотрудник всегда работает в своей line:номер, даже если подменил scope в запросе. У начатого звонка остаётся прежний снимок. События не перескакивают обязательные проверки личности/талона и не создают записи. При совпадении события своей линии оно имеет приоритет над глобальным. Непроверенные персональные версии основного телефонного сценария не активируются этим механизмом.

## Воспроизведение проверки

```bash
CLINIC_PYTHON=/tmp/clinic-ml-venv/bin/python PYTHONPATH=runtime/src:. python -m pytest tests/integration
node debug/run_admin_scenarios.mjs
EDITOR_URL=http://localhost:8090 EXPECT_CUDA=1 OUT_DIR=debug/runs/admin-scenarios/voice-only node debug/run_observer_speech.mjs
EDITOR_URL=http://localhost:8090 EXPECT_CUDA=1 OUT_DIR=debug/runs/admin-scenarios/microphone node debug/run_observer_call.mjs
```

При недоступности DNS обычная Docker-сборка не скачивает зависимости. Локальная альтернативная сборка, **только поверх установленных образов этого проекта**, не меняет зависимости:

```bash
npm --prefix scenario-editor run build
python tools/check_space.py
python tools/update_local_images.py
docker compose -f compose.yaml -f compose.gpu.yaml up --no-build -d --wait crm nlu agent sms operator tts asr scenario-editor
```

Точные исходные/получившиеся image ID и журналы сохраняются в debug/runs/admin-scenarios/. Это не результат полной сетевой пересборки. `docker compose stop` сохраняет данные. Не удалять том editor-data, если нужен архив.
