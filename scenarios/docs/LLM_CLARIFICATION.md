# Уточнение времени и сложного ФИО

Проверено 23.10.2026. Это небольшая модель для разбора непонятной реплики и вопроса пациенту. Ночной reasoning-агент восстановления МИС остаётся отдельным модулем.

## Разделение работы

Обычные ФИО, отдельные недостающие поля, даты и известные интервалы разбираются локально. ФИО владельцев входящего номера помогают определить, какая часть имени произнесена. Подсказка не заполняет недостающее отчество или дату рождения и не подтверждает личность. При общем номере и несовпадении человека нужны дополнительные проверки.

При сложной диктовке по буквам вызывается `DialogueModel.extract_spelling`. Модель получает реплику и подсказки ФИО владельцев. Допустимые значения ограничены целыми произнесёнными словами и проверяемыми последовательностями букв. `эль, и` может дать `Ли`; `им` из `Ким` и одиночное `эль` вместо всей фамилии отвергаются. Пропуски спрашиваются обычным шаблоном. Перед идентификацией обязательны полный год рождения и подтверждение прочитанных данных; для исходящего напоминания дополнительно проверяется владелец записи.

Непонятые предпочтения времени сохраняются вместе с исходной репликой. Все ветки поиска талонов, включая перенос, останавливаются перед МИС и входят в [time_clarification.flow](../time_clarification.flow). Непонятный ответ на предложение времени также передаётся в этот сценарий. `nlu.resolve_time` вызывает LLM через настроенный API; модель возвращает интервал или уточняющий вопрос. Даты и запреты дней сохраняет код. LLM не получает инструменты МИС и не выбирает/не записывает талон.

Для «после обеда и до полуночи» учитываются стандартные части дня регламента и явная верхняя граница конца суток: 12:00–24:00. «После двух часов дня» остаётся строго после 14:00. `24:00` допускается только как верхняя граница, а не начало дня. Для «после работы» нельзя выдумывать личное время окончания работы: требуется вопрос. Если модель всё же предлагает неподкреплённые часы, предложение отклоняется и запрашивается вопрос.

Любое предложение интервала сначала зачитывается пациенту. Только отдельное «да»/клавиша 1 вызывает `nlu.confirm_time`, после чего автомат возвращается к прежнему запросу слотов. Это согласие на интервал; запись требует нового подтверждения конкретного талона. Отказ, таймаут, недоступность модели и медицинское обращение не подтверждают запись.

## Запуск и API

Локальный профиль: `./clinic start --gpu --dialogue --no-build` после сборки образов. В настройках модулей включается «Сложные уточнения ФИО и времени (LLM)», локальный провайдер `qwen3:1.7b`. На проверенном стенде настройка уже включена. `dialogue-init` выполняет реальный прогрев перед запуском CRM/NLU. Одной загрузки весов недостаточно: первый холодный запрос превышал 8 секунд. Обычный API-запрос ограничен 8 секундами; при отклонении неподкреплённого времени разрешён второй такой запрос для вопроса. Reasoning локального помощника отключён. В CI/act/Actions генеративные запросы запрещены независимо от настроек.

Внешний провайдер использует тот же проверяемый JSON-контракт, но отдельные настройки «Совместимый API»: базовый URL, модель и имя локального ключа. Для предоставленного пользователем адреса можно задать `https://hub.gigaschool.ru/api/v1/llm/v1`, модель `ai-sage/GigaChat3-10B-A1.8B`, имя `GIGASCHOOL_LLM_API_KEY`; ключ помещается локально в `secrets/gigaschool_llm_api_key.key` и не коммитится. Ключа на стенде сейчас нет: реальный внешний вызов не принят, хотя контракт адаптера проверен. Не подменять это успешным ответом заглушки.

## Фактическая проверка

- Настоящая Qwen через локальный API: два интервала и вопрос о времени после работы; две диктовки ФИО, включая `Семёнов` с `ё`. Сохранены также исходные ошибки маленькой модели. Принятые ответы после прогрева: примерно 0,6–0,9 секунды; это измерение конкретных реплик, не SLA всех звонков.
- [debug/run_llm_fallback.py](../../debug/run_llm_fallback.py): настоящий Rust FSM → работающий NLU HTTP API → LLM → подтверждение → повторный поиск талона. Все операции МИС выполняются в новой SQLite в памяти, команды записи запрещены; итог `inbound.book_offer`, созданных записей 0.
- Python-контракты проверяют оба транспорта, блокировку API в CI, неверные часы, выдуманные данные, перестановку дней, буквы и владельца исходящего визита. Rust проверяет каждый путь поиска, непонятый ответ, отказ, медицинское прерывание и отсутствие преждевременной записи.
- Доказательства: `debug/runs/llm-fallback/`; интерфейс открыт в Chromium, новый сценарий присутствует в общей справке, панель МИС справа. Аудиобанк с GPU ASR: 46/46. Это автоматическая проверка распознавания, а не субъективная оценка естественности голоса.

Не закрыты: реальный внешний LLM API без ключа; все возможные разговорные/иностранные ФИО; все даты и пересекающие несколько суток временные интервалы; старые HTTP/аудио фикстуры, ещё использующие идентификацию только номером карты. Общая конкурсная оценка и все workflow не объявляются прошедшими.
