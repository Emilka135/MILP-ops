# Рабочее место регистратора

Откройте `http://localhost:8090/registrar` (фактический порт печатает `./clinic status`).

| Вход | Возможности |
|---|---|
| Без пароля | Наблюдатель: ближайшие шаги сценария, список и детализация звонка, готовые записи; изменения запрещены сервером |
| `user` / `user` | Временный регистратор рабочего места `100`: разговоры своего номера, предложение исправления, прослушивание собственного текста |
| `admin` / `admin` | Общий конструктор, аудиобанк, учётные записи; можно посмотреть мастерскую нужного номера |

Для отдельного сотрудника администратор нажимает «Сотрудники»: имя, логин, рабочий номер и пароль. Номер берётся из серверной учётной записи, подмена поля браузера не даёт доступа к другому номеру. Новый пароль завершает прежние сессии сотрудника. Пароли хранятся scrypt-хешами; файл учётных записей доступен только владельцу. Временные `admin` и `user` оставлены по указанию заказчика.

Выберите разговор или введите его номер. Показываются настоящая расшифровка и маршрут. Нажатие на реплику открывает соответствующий шаг. Здесь видны соседние шаги, а не вся карта будущих вариантов. В аудиоплеере — реальная запись; ошибка TTS показывается явно.

«Улучшить этот шаг» открывает простые поля: название случая, тема обращения, альтернативные формулировки и хороший ответ. В «На каком шаге ответить» можно выбрать только предыдущий шаг этого разговора. «Посмотреть реплики» показывает реплики и позволяет послушать ответ, без выполнения записи в МИС. «Предложить исправление» сохраняет исходный разговор и размеченные примеры атомарно.

Вкладка «Предложения» показывает фактический статус: очередь, ночная подготовка, проверка или испытание. Подготовленный пример не обозначается как работающая версия. Время интерфейса сохраняет дату клиники, а не сдвигает полночь в часовом поясе браузера.

## Панели и схема работы

По умолчанию слева находится архив звонков, справа — фактические ответы МИС или тестовой базы, в центре — разговор. Перетяните заголовок боковой панели к любому краю рабочей области; отпустите в середине, чтобы получить отдельное окно. Те же действия доступны через список расположения в заголовке. Стрелки на сфокусированном заголовке закрепляют панель к соответствующему краю; Escape отменяет перетаскивание.

Граница панели меняет её ширину или высоту мышью. Стрелки на сфокусированном разделителе меняют размер, Home/End выбирают минимум/максимум; у отдельного окна горизонтальные стрелки меняют ширину, вертикальные — высоту. Расположение и размер сохраняются в этом браузере. «Вернуть исходный вид» восстанавливает звонки слева и МИС справа. На узком экране панели выстраиваются последовательно: звонки, центральная область, МИС; сохранённая desktop-раскладка остаётся доступна на широком экране.

Тема в нижней строке — светлая, тёмная или системная — действует только на рабочее место. Административный редактор сохраняет свой интерфейс. Код раскладки сохраняет в браузере настройки расположения и темы; клиентская база данных в браузере не создаётся. Источник оформления — единственный предоставленный HTML-эталон; [MIT notice](../../scenario-editor/THIRD_PARTY_NOTICES.md) сохранён.

Во вкладке «Разговор» нажмите строку расшифровки для просмотра соответствующего шага. Во вкладке «Автомат» показывается фактический сохранённый путь, с сохранением повторных посещений шагов. «Пробный звонок» открывает существующий клиент настоящего ASR/TTS/автомата; его обращения остаются в изолированной тестовой картотеке. Панель справа показывает источник, номер выбранного звонка, сохранённый результат и статус проверки. Для каждой ячейки, включая NULL, пустую строку и JSON, есть копирование; параметры и текст запроса находятся в раскрываемых подробностях. Снимок SQLite не называется внешней МИС.

«Схемы / Справка» читает настоящий серверный каталог `scenarios/`: схемы `.flow`, документацию, регламент, инструкции и контракт МИС. Шаг можно выбрать по его имени, прочитать реплики и перейти по связям. Документы показываются как исходный текст; HTML и скрипты из них не выполняются. Администратору доступна ссылка в существующий общий редактор. Сотрудник может предложить правку выбранного шага только через звонок своей линии, где этот шаг встречался; это очередь проверки, а не изменение общего сценария. Если каталог недоступен, интерфейс сообщает об этом и показывает доступный шаг workshop API, не подставляет вымышленные документы.

Направления и сроки их действия не извлекаются из предоставленной МИС: возможный источник — только отдельно подключённый локальный реестр клиники. Просмотр схем/документов не выполняет транзакции МИС.

## Что уже подключено, а что ещё ожидает реализации

Архив сохраняется Rust-движком в CRM: номер регистратора, фразы пациента после настоящего ASR, DTMF, ответы, маршрут и исход звонка. Длинные последовательности цифр скрываются в учебной расшифровке. Копия в браузере не заменяет оригинальный телефонный журнал.

Ночной контейнер вызывает `learning.night`; CRM проверяет закрытие по той же таблице часов, что используется для перезвона. Пока это локальная подготовка размеченных формулировок и тем, **нейросеть не обучается**. Предложение получает статус «подготовлено», но ещё не меняет ответы или порядок живого звонка. Произвольная строка «проверенная ревизия» не разрешает активацию.

Развёртывание персонального варианта, проверка зависимостей данных, жалобы, измерение эффекта и откат остаются открытыми пунктами [TODO](../../TODO.md). Дата «самое раннее начало» означает ограничение эксперимента, а не обещание уже состоявшегося включения. При недоступной CRM движок фиксирует ошибку архива; долговременная резервная очередь архива ещё требуется.

## Приёмка

```bash
PYTHONPATH=runtime/src:. python -m pytest -q tests/integration/test_learning.py tests/integration/test_scenario_editor.py tests/integration/test_workshop_access.py
npm run build --prefix scenario-editor
node debug/run_registrar_mis_panel.mjs
node debug/run_registrar_scenario_actions.mjs
```

Браузерные прогоны используют локальный тестовый стек `28480` и редактор `28490`; адреса можно задать `ORCHESTRATOR_URL` и `EDITOR_URL`. В `debug/runs/workshop/browser/` лежат настоящий входной WAV, фактическая ASR-фраза и снимки разметки. В `debug/runs/voice-controls/` — вход user/user, наблюдатель с деталями, проигрывание администратором и проверка формы учётной записи. Серверные проверки отдельно доказывают запрет записи наблюдателю и привязку номера.


Дополнительные актуальные UI-доказательства: `debug/runs/registrar-mis-panel/`. Первый runner использует настоящий Chromium/clipboard и явно синтетические HTTP-ответы для проверки интерфейса. Второй поднимает настоящие editor/Repository/Learning/SQLite на своих временных портах: admin save/restore, чтение реального knowledge API, scoped-предложение из схемы и серверные ACL. Он проверяет отображение синтетического архива; настоящий ASR/исполнение FSM этим прогоном не заявляется. Для архива из отдельного Session runner поддерживается `SCENARIO_ACTIONS_ARCHIVE` с независимым `expected_target`.
