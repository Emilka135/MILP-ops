# Развёртывание командного стенда GIGASCHOOL

Проверено 21.10.2026 на VM: 4 CPU, 8 GiB RAM, без GPU. Локальный GPU-профиль проекта не меняется. Актуальные доказательства: `debug/runs/vm-deployment/`.

## Проверенный результат

- Публичная мастерская: HTTPS-домен команды из панели VM, путь `/registrar`. Вход VM слушает `0.0.0.0:8000`. Корневой redirect относительный, внутренний порт не попадает в браузер.
- ASR: локальный GigaAM v3 ONNX int8 на CPU. TTS: Silero CIS MIT, `ru_ekaterina`; E5 NLU также локален. Аудио и ФИО не отправляются в LLM.
- Агент использует реальный командный шлюз, модель `GigaChat/GigaChat-3-Pro`. Передаются только допустимые ID слотов, даты/время и ограничения. Запись выполняет CRM после отдельного согласия, а не модель.
- DBI: реальный импорт всех 85 врачей по точному полному имени; номера `D001` из XLSX не используются как API ID. Импортировано 42 311 явно свободных слотов из официального файла. Даты в прошлом и занятые слоты не предлагаются; занятость DBI синхронизируется отдельно.
- Голос, звуковой DTMF и смешанный ввод независимо прошли Rust → LLM → создание DBI. Для нового тестового визита также проверены перенос и отмена. Все созданные при приёмке визиты отменены; история API остаётся у организаторов.
- SIP: Asterisk 22.11.0 зарегистрирован на выданном шлюзе, номер 114; реальные звонки с учётки телефона команды дали двустороннее G.711-аудио. ARI слушает только loopback `18088`, поскольку `8088` занят файловым менеджером VM.
- Аудиобанк: 41/41 настоящих записей прошли ASR/сигнальный контроль. 143 целевых регрессионных теста прошли.

Веб-пробник работает в отдельной тестовой SQLite. Его успешный звонок сам по себе не доказывает запись в DBI: для этого сохранены отдельные `live/*/result.json` и `events.json`.

## Повторный запуск установленной копии

Рабочая копия при установке: `~/clinic-voice`. Секреты хранятся в её игнорируемом `.env` и `secrets/`; исходные ключи организаторов — `/opt/hackathon/ai.env` и `/opt/hackathon/sip.env`.

```bash
cd ~/clinic-voice
python3 tools/check_space.py
docker compose -f compose.yaml -f compose.vm.yaml up -d --no-build orchestrator scenario-editor proxy
docker compose -f compose.yaml -f compose.vm.yaml --profile telephony up -d --no-build --no-deps telephony ari-bridge
docker compose -f compose.yaml -f compose.vm.yaml ps
curl --fail http://127.0.0.1:8080/readyz
curl --fail http://127.0.0.1:8000/health
docker compose exec -T telephony asterisk -rx 'pjsip show registrations'
```

Если `audio-check` завершился с ошибкой, выпуск блокируется: смотреть его журнал, исправлять запись и повторять аудит. Не заменять его тишиной и не отключать зависимость.

Остановка с сохранением томов:

```bash
docker compose -f compose.yaml -f compose.vm.yaml --profile telephony down
```

Не добавлять `-v`: SQLite, настройки и аудиобанк должны сохраняться.

## Подготовка чистой VM

1. Использовать Python 3, Docker и Compose v2. На выданной Ubuntu устанавливается пакет `docker-compose-v2`. До сборок и скачивания запускать `tools/check_space.py`, оставляя больше 10 GiB на `/home` и 5 GiB на `/`.
2. Клонировать репозиторий. Создать закрытый `.env` из полученного командного файла; не коммитить и не выводить `docker compose config` с раскрытыми значениями. Нужны `APP_MODE=live`, `WITH_ML=1`, `STAND_URL` с `/api/v1`, `DBI_API_TOKEN`, случайные `API_TOKEN`/`ARI_PASSWORD`, `EDITOR_LOGIN_PASSWORD`, параметры командного LLM и пути импортов.
3. Подготовить `secrets/ari.conf` с пользователем `calls`, паролем из `ARI_PASSWORD`, `enabled=yes` и `read_only=no`. Файл читается контейнерным UID 10001; каталог остаётся закрытым для других пользователей. Приложить выданный организаторами `/opt/hackathon/sip/pjsip.conf` как read-only mount, не копировать его в Git.
4. Собрать **все** необходимые образы, включая `nightly` и `ari-bridge`:

```bash
COMPOSE_PARALLEL_LIMIT=2 docker compose -f compose.yaml -f compose.vm.yaml --profile telephony build
```

5. Скачать локальные модели штатными `tools/download_models.py --tts --asr` и `tools/download_nlu.py` в ML-окружении или соответствующем контейнере с корнем проекта, смонтированным в `/workspace`. Скачивание проверяет контрольные суммы. Сохранить доступ контейнерного пользователя к моделям и импортам; секреты не делать общедоступными.
6. Скачать оригинальный XLSX из материалов кейса в `data/raw/official-schedule.xlsx`. Получить страницы `/doctors?limit=50&offset=0` и `offset=50` с командным Bearer-токеном и сохранить JSON. После этого выполнить:

```bash
python tools/import_dbi_schedule.py \
  --workbook data/raw/official-schedule.xlsx \
  --doctors debug/runs/vm-deployment/doctors-page1.json debug/runs/vm-deployment/doctors-page2.json \
  --output imports/official-schedule.csv \
  --report debug/runs/vm-deployment/schedule-import.json
```

7. Указать `CRM_SCHEDULE=/imports/official-schedule.csv`. Пациентов импортировать по доверенным карточкам; организатор разрешает исключительно вымышленные данные. Проверенные при приёмке синтетические карты: `1001`, Тестов Иван Иванович; `1002`, Иванов Иван Иванович; обе с датой рождения `01.01.1990`. Номера карт не являются ID клиентов DBI.
8. Выполнить команды запуска выше; проверить HTTPS браузером, вход администратора и настоящую SIP-регистрацию. `EDITOR_BOOTSTRAP_PASSWORD` применяется только к новой установке, смена `.env` не перезаписывает существующий хеш пароля. В размещённой копии стандартные `admin`/`user` заменены локальным паролем, сохранённым в закрытом файле команды.

## Приёмка без подмены аудио

Из корня проекта, используя образ CRM как тестовый клиент:

```bash
docker run --rm -u 0 --network clinic-voice_clinic --env-file .env \
  -e PYTHONPATH=/workspace:/workspace/runtime/src -v "$PWD:/workspace" -w /workspace \
  --entrypoint python clinic-voice-crm debug/run_vm_live.py --mode tones-only
```

Повторить отдельно с `--mode speech-only` и `--mode combined`. Прогон **изменяет DBI**, использует только указанные вымышленные карточки, создаёт новый визит и отменяет только его. Не запускать на данных пациентов. Для SIP используется `debug/run_vm_sip.py`: контейнеру нужны host network, read-only `/opt/hackathon/sip` → `/organizer` и `/opt/hackathon/sip.env` → `/organizer-env/sip.env`; отдельные режимы `speech`/`tones` совершают информационный звонок на собственный номер команды.

## Честные ограничения

- SMS-шлюз организаторами не выдан: очередь сохраняется, доставки SMS не заявляем. Тестовые карты не содержат настоящих телефонов.
- `OPERATOR_AVAILABLE=0`: автоматическая очередь не выдаётся за ответ живого регистратора. Нештатные обращения сохраняются; dialplan передачи на командный софтфон предусмотрен, но фактический ответ сотрудника не принят.
- `POST /escalations` пока не подключён. Проектная локальная карточка оператора и внешняя заявка DBI — разные действия.
- Исходящий массовый обзвон выключен: `OUTBOUND_ENABLED=0`. Расписание кампании, согласие и антифрод должны быть настроены отдельно.
- Регистрация совершенно нового пациента голосом ещё не принята: основной сценарий ищет доверенную карточку; при отсутствии предлагает сотрудника.
- Фамилия «Тестов» в одном настоящем ASR-прогоне распозналась как «Тистов»; личность была отклонена. Успех синтетического корпуса не заменяет тесты живых говорящих, шумов и акцентов.
- Влияние на пропущенные звонки/неявки и конкурсные баллы пока не измерены. Цели кейса не выдаются за достигнутые показатели.

## Польза клинике и следующий пилот

Целевая боль — 30–40% пропущенных звонков и перегрузка регистратуры. Пилот: один телефонный номер, запись/перенос/отмена и справки, с живым сотрудником для сложных обращений. Измерять долю завершённых типовых звонков, ожидание, ошибки записи и удовлетворённость; целевые пороги кейса — пропуски до 15%, автоматизация от 60%, ожидание до 30 секунд. Масштабировать после наблюдаемого результата, а не по одному healthcheck.
