Файлы расписания и пациентов кладутся сюда локально; форматы CSV/XLSX описаны в docs/STAND.md. Не коммитьте выгрузки с персональными данными.

## Исходные CSV и Excel из корня prodxak

Импортировать все три выданных файла, сохранив их пути и SHA256:

```sh
.venv/bin/python tools/import_clinic_sources.py
```

Скрипт по умолчанию ищет два UUID CSV и `Расписание_врачей_25.06-31.12.2026.xlsx`
в родительском каталоге checkout; другой каталог задаётся `--source-root`.
Результат — `imports/clinic-source.sqlite`. Сценарный редактор монтирует `imports`
только для чтения и автоматически подключает снимок как SQLite-схему `source`.
Явный путь внутри контейнера можно задать через `CLINIC_SOURCE_DB`.
Повторный импорт атомарно заменяет снимок; после него перезапустите
`scenario-editor`, чтобы соединения открыли новую версию файла.

В снимке находятся 85 врачей, 136973 слота, 135 периодов недоступности,
35470 строк истории приёмов и 17772 события звонков. Числа проверяются по файлам,
а не используются для генерации данных. Их отсутствие при запуске обозначается
как отдельный режим синтетических тестовых данных.

Из этих файлов нельзя восстановить ФИО и даты рождения пациентов, полисы,
привязки участков, направления или расшифровки звонков. Тестовая идентификация
остаётся в явно обозначенной отдельной картотеке. Привязка участка к врачу
записывается только по подтверждённым данным в `district_doctors`; отсутствие
связи вызывает уточнение и передачу регистратору, а не выбор произвольного врача.
Запись в демонстрации сохраняется в отдельную таблицу и не изменяет исходные файлы.
Это файловый снимок, а не заявленная синхронизация с МИС.

В мастерской `/registrar` слева видны фактически выполненный SQL, связанные
параметры, строки ответа и исходные файлы с датой импорта. Ширина панели меняется
перетаскиванием разделителя или стрелками клавиатуры; двойной щелчок сбрасывает её.
SQL пока формирует модуль по параметризованным шаблонам, а не LLM.
